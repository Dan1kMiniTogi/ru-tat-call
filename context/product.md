# Продукт и требования (SRS)

## Цель

Разработать self-hosted видеосвязь с потоковым ASR и субтитрами в реальном времени. Главная особенность — мультиязычная речь и **смешанные предложения** (татарский + русский, иногда вставка на другом языке) без ручного переключения языка.

Клиент: Android и iOS, одна кодовая база. Обработка речи — на **своём ASR-сервере**, который контролирует владелец.

## Для кого

Семейный сценарий. Все пользователи с одинаковыми правами. Ролей admin/moderator в MVP нет. Одна группа пользователей, один активный звонок, один домашний ASR и один signaling.

## Сценарии

- **UC-01** Открыть приложение → контакт → исходящий видеозвонок.
- **UC-02** Принять звонок → WebRTC → аудио/видео.
- **UC-03** Речь участников уходит на ASR → partial/final субтитры на экране звонка. Пользователь не жмёт «начать распознавание».
- **UC-04** Свободный code-switching внутри разговора (tt → ru → английское слово → tt).
- **UC-05** Несколько участников: каждая реплика с именем говорящего.

Пример смешанной фразы из ТЗ: `Әни, сегодня магазинга барасыңмы?`

## Функциональные требования MVP

| ID | Требование |

| F-01 | Авторизация |
| F-02 | Список контактов |
| F-03 | Исходящий звонок |
| F-04 | Входящий звонок |
| F-05 | Групповой звонок, максимум **4** |
| F-06 | Видео |
| F-07 | Аудио |

## Нефункциональные

- **Latency субтитров:** желательно 300–700 мс, в типичных условиях **< 1000 мс**. Постоянно 1.5–2 с — плохо.
- **Масштаб:** заменить модель, сервер, железо (ноут → домашний сервер → mini-PC → VPS) без смены архитектуры клиента.
- **Отказоустойчивость:** ASR недоступен → звонок живёт, субтитры гаснут, есть предупреждение.
- **Безопасность:** TLS, обязательная аутентификация, секреты не в клиенте, нет анонимного публичного доступа.
- **Приватность по умолчанию:** не писать аудио, видео, транскрипты. Сохранение текста — явная отдельная настройка.

## Вне MVP (намеренно)

Текстовый чат, файлы, соцфункции, истории сообщений, реакции, стикеры, каналы, запись A/V, обязательный перевод, AI-ассистент в звонке, сложные push, публичный discovery пользователей, диаризация как обязательный слой.

Примечание: в SRS «статусы пользователей» исключены, в архитектуре/API у контактов есть `online/offline`. Для MVP достаточно лёгкого presence в signaling, без «социального статуса» как фичи.

## Критерии готовности MVP

Два клиента (Android и iOS) в одном звонке до 4 человек; приемлемые A/V; live-субтитры; mixed RU/TT без ручного языка; latency типично ≤ 1 с; свой ASR; отказ ASR не рвёт звонок; модель заменяется без переписывания клиента.
